# CRUSH.md

Build/lint/test
- Build: go build ./...
- Run CLI: go run .
- Install locally: go install ./...
- Format: go fmt ./...
- Vet (static checks): go vet ./...
- Lint (if golangci-lint installed): golangci-lint run ./...
- Test all: go test ./...
- Test verbose: go test -v ./...
- Test single package: go test ./cmd
- Test single file: go test -run TestName ./pkg || go test -run TestName ./...
- Test single test: go test -run ^TestName$ ./...

Code style
- Go version: per go.mod toolchain; use stdlib first, then external, then internal imports; group with blank lines, sorted.
- Formatting: always run go fmt; no custom formatters; keep lines concise.
- Types: prefer explicit types in public APIs; return concrete types unless interfaces are needed; use time.Duration, context.Context as first param when needed.
- Naming: exported identifiers use CamelCase with meaningful names; unexported are lowerCamelCase; acronyms in caps (HTTP, URL, ID); files and packages are short, lower_snake if multiple words.
- Errors: use error values; wrap with %w (fmt.Errorf) for context; avoid panics in library code; sentinel errors via var; check and handle errors immediately.
- Context: pass context.Context as first param in long-running or I/O funcs; honor cancellation and deadlines.
- Logging/IO: avoid printing in packages; return errors to caller; CLI code can print using fmt.
- Concurrency: guard shared state; prefer channels over mutexes only when it clarifies; use context for goroutines; avoid leaks.
- CLI: follow cobra patterns in cmd/; keep command wiring in init_commands.go and root.go; business logic lives in packages (e.g., editor/).
- Config: viper for config, cobra for flags; do not log secrets; read OPENROUTER_API_KEY from env when present.
